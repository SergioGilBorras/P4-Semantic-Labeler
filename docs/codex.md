# Codex provider

Set `P4_LABELER_PROVIDER=codex` and install [P4-Codex-Bridge](https://github.com/SergioGilBorras/P4-Codex-Bridge) version **1.1.0 or later** with a supported installed, authenticated official Codex CLI. Install from the merged `main` checkout. For a fresh checkout, run `git clone https://github.com/SergioGilBorras/P4-Codex-Bridge.git`, then `python -m pip install -e ./P4-Codex-Bridge` in the labeler's active environment. For an existing checkout, update it with `git switch main` and `git pull --ff-only origin main` before installing. The bridge is an optional runtime integration: it is imported only for Codex requests, and the Python library and mock provider do not require it.

`cwd` is the working directory in which the Codex CLI process runs; it does not specify the bridge's state storage. For a managed workspace, the adapter creates a unique temporary run directory containing separate `workspace` and `bridge-state` children. The workspace is empty and disposable, so the adapter passes `skip_git_repo_check=True` to the public `CodexBridge.run()` API; this skips only the CLI's Git repository check and does not initialize Git. The bridge state directory remains separate and is not added to `allowed_roots`.

If `P4_LABELER_CODEX_WORKSPACE` names an existing external directory, the adapter preserves it, creates bridge state under the managed temporary root, and uses `skip_git_repo_check=False`. It does not modify that external workspace.

The adapter sets `profile="analysis"`, `config_policy="isolated"`, `capture_last_message=True`, `SandboxMode.READ_ONLY` and `ApprovalPolicy.NEVER`. It passes a combined instruction and JSON reference-data prompt, because `run()` accepts one prompt string rather than separate system/user roles. It consumes the final `RunResult.content` and rejects unsuccessful/empty results. A missing `skip_git_repo_check` capability or a bridge version older than 1.1.0 produces a safe capability diagnostic before a provider call.

In either mode, `allowed_roots` contains only the selected workspace; bridge state is never included. Protect an external workspace and avoid untrusted Codex configuration or `AGENTS.md` there. Input source code is included as **prompt text**, never written to the working directory or executed by this service.

**External MCP risk:** inherited MCP tools are not isolated by the temporary workspace, `skip_git_repo_check`, or the filesystem sandbox. An external MCP can cause side effects even with read-only filesystem permissions. The adapter therefore passes `RunSecurityPolicy(project_trust=TRUSTED, allow_external_mcps=True, allow_side_effect_mcps=True, explicit_risk_acknowledgement=True)` when a user selects Codex. This acknowledges the risk; it does not provide MCP isolation or guarantee that external MCP tools are read-only. Operators must control which MCP servers their Codex installation exposes.

The bridge uses the Codex CLI's existing authentication. This project stores no Codex credentials. `P4_LABELER_PROVIDER_TIMEOUT` is forwarded to bridge calls; service-side async timeout cannot always terminate an already running thread immediately, although the bridge also enforces its own process timeout.

The integration is covered by mocked public-interface tests. Real inference requires Codex CLI login and availability; CI does not run live, paid inference. `GET /health` only confirms the labeler process is alive, not Codex availability.
